# AI API 重试预算清单：SDK、业务层与任务队列

![AI API 重试预算清单：SDK、业务层与任务队列](cover.png)

用于审查一次逻辑任务可能发出的请求数量和总耗时。先区分最大尝试次数与额外重试次数；以实际 SDK 配置定义为准。

## 分层盘点

| 层 | 需要记录 |
| --- | --- |
| SDK | 自动重试、可重试错误、单次超时 |
| 业务代码 | 最大尝试次数、整体截止时间 |
| 队列 | 重新投递与重复消费条件 |
| 服务端 | 等待提示、任务查询、幂等语义 |

机制示例：若业务层最多 3 次尝试，每次 SDK 最多 3 次 HTTP 尝试，两层都持续触发时最多 9 次；尝试次数包含首次请求。这不是线上事故记录。

## 审核清单

- [ ] 尽量由一层负责重试；保留多层时算入整体预算。
- [ ] 认证、参数、权限和明确长期配额问题先处理原因。
- [ ] 有效 `Retry-After` 可能是秒数或 HTTP 日期，不能提前重发。
- [ ] 提示等待时间超过业务预算时停止或交回队列。
- [ ] 无有效等待提示时使用有上限的退避与随机抖动。
- [ ] 新任务的发送速度、并发和 Token 用量一并受控。
- [ ] 异步提交超时后先按接口规则查询，避免重复生成。
- [ ] 仅在服务明确支持时依赖其幂等键，不假定任意接口都去重。

退避不会提高服务容量。可重试错误、任务是否允许重复执行和整体耗时要共同决定策略。
